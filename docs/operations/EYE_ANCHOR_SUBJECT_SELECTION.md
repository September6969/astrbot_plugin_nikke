# 人物眼部锚点主体选择（2026-10-20）

本次修复生产 `integrations/spine/portrait_anchor.py` 的自动锚点选择，不依赖角色 ID 或乌鸦名称黑名单。

## 已确认问题

哈兰现场缓存没有 worker geometry，因此使用整图适配；补充静态锚点的 PR #123 已处理现有匹配像素。进一步回放实际骨架几何发现：旧自动算法合并人物和乌鸦眼睛，且遗漏 eyehole、接受 hl 高光。仅升级 worker 不能解决此问题。

## 新规则

1. 眼睛候选识别补充 eyehole，排除 hl 高光，保留原来的眼罩、眉毛等排除项。
2. 按父骨分组，无父骨时使用所属骨；无归属信息的旧响应保留独立分组。
3. 只有一个分组时保留单眼兼容；多个分组时，仅在唯一分组明确含左右眼时使用该组。
4. 两组左右眼都成立、多个单眼组均无法确认时返回 ambiguous_eye_subjects，不合并中心。
5. 即使共用根骨，若联合宽度超过最大单附件宽度的 6 倍，或联合高度超过最大单附件高度的 3 倍，也拒绝合并。这是保守的异常距离阈值，不是人体识别模型。
6. 锚点 schema 从 2 升为 3，沿用现有旧缓存一次性补算机制。工具仍不提供 geometry 时记录不可用，不伪造坐标。

## 证据与边界

- 仓库 fixture 保存哈兰实际骨架的最小眼部附件几何，测试不依赖远端、图片或用户账号。
- 原逻辑在新增的四个核心回归上失败；修改后通过，另覆盖共享根骨、旧字段缺失和编号骨架。
- 实际哈兰骨架经过裁切变换、PNG 保存重读、禁用静态表后，仍得到眼部点 (565.1978358283856, 203.6509413073598) 和 2.94 倍取景。
- 归属判断是保守启发式，不能保证识别任意宠物或任意多人物骨架；分开的左右眼父骨、特殊命名可能降级为不可用。
- 离线 `extract_spine_face_anchor.mjs` 仍输出宽松候选，只供人工诊断，不代表新版生产选择结果；不能把其眼睛联合范围未经复核直接发布为静态锚点。
- 本轮未修改服务器 worker 或部署；服务器仍需安装能输出 geometry 的 worker 才能为新图片自动生成锚点。
