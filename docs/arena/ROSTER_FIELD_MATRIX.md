# 角色名单字段矩阵

代码证据来自 integrations/blablalink/client.py 的 get_roster 与现有角色主表。2026-11-17 19:58 PST，用户用真实绑定账号执行 `竞技场 我的`，回报 同时包含已映射和未映射角色。实测证据来自命令的公开字段，无原始名单。

| 字段 | 代码合同 | 本轮实测 | Arena 用途 |
|---|---|---|---|
| name_code | 网关完整性检查要求存在 | 确认有成功映射和未映射条目 | 唯一用于映射持有基础角色 |
| 名称及妮姬规范 ID | 本地主表可解析 name_code | 已观察到映射总数 | 由本地主表补全 |
| lv、combat | 老测试包含部分样本 | unknown | 当前计算不读取 |
| skill1_lv、skill2_lv、ulti_skill_lv | 完整详情模式额外请求后合并 | unknown | 轻量路径视为缺失 |
| 珍藏品阶段 | 轻量名单合同没有保证 | unknown | 绑定持有不推断珍藏状态 |
| favorite_item_tid（单角色详情） | 仅读取网关 30 秒短缓存内已有的详情，不额外请求 | 待生产验证 | 与 registry 专属珍藏品一致才标「官方详情确认」；不一致标为官方未装备；无详情只作「基础名单推测」提示 |
| 魔方 | 轻量名单合同没有保证 | unknown | 输出缺失 |
| 装备、超频及收藏品细项 | 单角色详情可提供部分数据 | unknown | 当前名单端口不调用 |
| 原始 Cookie、X-Common-Params | 只供原账号网关使用 | 私密 | 不进入 Arena DTO 或网页 |

名单出现未知 code 或非对象时，排除对应项并标记 partial。空的有效名单代表没有确认可用的角色。未绑定、失效或超时时，私聊个人模式提示检查绑定，用户可显式改用沙盒。

群聊公开分析不调用私人名单。网页只通过 token 兑换后的服务器会话确定 actor_id。请求体中增加 actor_id 会因未知字段被拒绝。
